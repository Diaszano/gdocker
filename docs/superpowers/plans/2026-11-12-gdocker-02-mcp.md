# gdocker Plano 2 — Servidor MCP, permissões e aprovação

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** O app roda um servidor MCP local com token, expõe as ferramentas de container, aplica o sistema de permissões Permitir/Perguntar/Negar com aviso de aprovação, registra a atividade da IA e oferece a ponte `--stdio`.

**Architecture:** A política mora em `GDockerCore`, sem dependência do SDK MCP e testável com fakes: catálogo de ferramentas, `PermissionStore`, `ApprovalQueue`, `ActivityLog` e o `ToolRouter`, que valida, decide a permissão e executa via o protocolo `DockerOperations`. Um alvo novo `GDockerMCP` liga o router ao SDK oficial (HTTP em `127.0.0.1` com adaptador SwiftNIO, token e validação de Origin) e traz a ponte stdio. O app (`GDocker`) só adiciona o controlador, as telas e o painel de aprovação.

**Tech Stack:** Swift 6.3, SwiftUI, [modelcontextprotocol/swift-sdk](https://github.com/modelcontextprotocol/swift-sdk) `from: "0.12.1"` (produto `MCP`), swift-nio `from: "2.65.0"`, Security.framework (Keychain), Swift Testing.

**Spec:** `docs/superpowers/specs/2026-11-12-gdocker-design.md`. Parte do Plano 1 (`docs/superpowers/plans/2026-11-12-gdocker-01-core.md`, já na `main`).

**Fora deste plano (Plano 3):** Imagens/Volumes/Redes/Compose (UI e ferramentas `list_images`, `list_volumes`, `list_networks`, `list_compose_projects`, `remove_image`, `remove_volume`, `remove_network`, `system_prune`, `compose_up`, `compose_down`), aba Terminal e cask. O catálogo e as telas deste plano são feitos para receber essas ferramentas só acrescentando entradas em `ToolCatalog.all`.

## Global Constraints

- macOS mínimo **14**; `swift-tools-version:6.1`; todo comando `swift` com `DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer` (o `Makefile` já exporta). Testes: `make test`.
- Servidor MCP em `127.0.0.1` (nunca outra interface), porta padrão **7391**, configurável. HTTP Streamable, endpoint `/mcp`.
- Toda requisição exige `Authorization: Bearer <token>`; o token é gerado na 1ª execução, guardado no Keychain, incluído no "Copiar config", e há um botão para gerar outro. `Host`/`Origin` que não sejam localhost são rejeitados (DNS rebinding). O nome do cliente vem do próprio cliente e serve só para exibir.
- Três estados por ferramenta: **Permitir**, **Perguntar**, **Negar**. Ferramenta desconhecida = Negar. **Negar** devolve erro explicando que o usuário bloqueou.
- Aviso de aprovação mostra cliente, ferramenta, argumentos e o `reason` (argumento opcional de toda ferramenta), com Negar / Permitir uma vez e a caixa "Sempre permitir" (muda a regra para Permitir). `exec_in_container`: a aprovação vale só para aquele comando e o aviso **não** mostra "Sempre permitir".
- Variáveis de ambiente saem **mascaradas** (`***`) em todas as respostas, menos em `get_container_env` (padrão Perguntar). Logs não são mascarados.
- `exec_in_container` roda um comando (lista de argumentos, sem shell) e devolve stdout, stderr e código de saída, sem sessão interativa.
- Acesso ao Docker só pela Engine API (nada de `docker` CLI neste plano).
- Strings visíveis ao usuário no catálogo `Sources/GDocker/Resources/Localizable.xcstrings` com **en** e **pt-BR**. Textos devolvidos à IA (erros e respostas das ferramentas, descrições das ferramentas) ficam em inglês.
- Commits sem trailer de co-autoria de IA (um hook do repositório recusa). Branch no formato `<tipo>/<descricao-kebab>` (hook); use `feature/mcp`.
- AsyncHTTPClient derruba o processo se um `HTTPClient` for descartado sem `shutdown()`: todo código novo que cria um `DockerClient` ou `HTTPClient` o desliga.
- O shell recusa heredocs e comandos compostos com `$(…)` no worktree isolado: use comandos simples e `Write`/`Edit`. Sem permissão de Acessibilidade não dá para clicar na UI: tudo que depende de clique vai para o ledger como `UNVERIFIED`; as demais verificações usam a ponte `--stdio`, `curl` e capturas de tela da janela (`screencapture -l <id>`).

## Review Focus

1. **Requisição sem token, com token errado, ou com `Origin`/`Host` não-local** é rejeitada (401/403) antes de qualquer ferramenta rodar. Testes na Task 7.
2. **Ferramenta negada, recusada pelo usuário, sem resposta dentro do prazo, desconhecida, ou com argumentos malformados:** o Docker nunca é chamado, a atividade é registrada e a IA recebe um erro que explica o motivo. Testes na Task 5.
3. **Vários avisos pendentes ao mesmo tempo, ou o usuário nunca responde:** fila FIFO, nenhum se perde, cancelar ou estourar o prazo tira o aviso e conta como negado. Testes nas Tasks 4 e 5.
4. **Saída enorme ou hostil e alvo ambíguo:** exec e logs têm teto (64 KiB e 2000 linhas), comando que não termina estoura o prazo, e nome de container ambíguo (nome vs prefixo de id) ou inexistente dá erro claro. Testes nas Tasks 3 e 5.
5. **Docker parado, porta ocupada ou arquivo de permissões corrompido:** chamadas devolvem erro "Docker is not connected" em vez de travar, a porta ocupada aparece como erro no status, e o arquivo corrompido cai para os padrões. Testes nas Tasks 1, 5 e 7.
